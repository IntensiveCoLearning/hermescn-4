# HermesCN 残酷共学第三期｜ 打造自己的内容创作助手

## 共学简介

前两期，我们完成了 Hermes 从安装和日常使用的学习，并尝试让 Hermes 完成一个真实任务。

第三期聚焦内容创作。

你可以带着一个想写的选题、一组尚未整理的笔记，或一个实际的社区内容需求加入。

七天围绕同一个项目，完成内容创作的工作流。

**明确创作方向 → 建立思考框架 → 研究与判断 → AI 辅助创作 → 编辑审核 → 自动化发布 → 复盘改进**

内容形式可以是文章、公众号、Newsletter、X 长帖、社区内容或视频口播稿。选择口播方向的同学，基础作业以脚本为主，不要求同时完成视频制作。

结营时，你将获得一篇完整作品、一份个人内容思考框架，以及一套经过测试的 Hermes 创作与发布工作流。

【基本规则】

* 周期：连续 7 天，每日投入约 45–90 分钟

- 形式：阅读短材料、动手实操、和群友深度交流学习

* 注意：不要泄露任何 API Key、Token、私钥等凭据，不让 Agent 未经确认执行危险操作。

## 共学内容 / 课程信息

### Day 1｜ 与 Hermes 一起明确创作方向

我准备写给谁？这个问题为什么值得讨论？我有什么材料可以贡献？

**实践任务**

1. 向 Hermes 介绍自己的兴趣、经历和内容需求，提供已有笔记或素材。
2. 让 Hermes 通过提问，帮助梳理目标读者、核心问题和可写的角度。
3. 自己选择一个七天内能够完成的选题，说明选择理由。
4. 让 Hermes 将确认结果整理成创作任务卡，保存到项目文档中。

**当日产出**

一份与 Hermes 共同完成的创作任务卡，包括选题、读者、内容形式、已有材料和预期成果。

**参考资料**

* HermesCN 中文教程，优先阅读基础使用、任务描述相关章节。\
  <https://hermescn.org/docs/tutorials>

* Google Technical Writing One，选读受众与内容范围相关部分。英文资料，可辅助翻译阅读。\
  <https://developers.google.com/tech-writing/one>

### Day 2｜ 让 Hermes 帮你检查思考框架

我的判断是什么？依据是否足够？什么信息会让我改变看法？

**实践任务**

1. 先用自己的话向 Hermes 说明初步看法，可以口述，也可以提交简短笔记。
2. 让 Hermes 帮助区分事实、假设和判断，指出依据不足或推理跳跃的位置。
3. 请 Hermes 提出有依据的反对意见，并通过追问帮助自己补充思考。
4. 自己决定保留、修改或暂缓哪些判断，让 Hermes 整理成第一版思考卡，并保留待验证问题。

**当日产出**

一张个人思考卡，以及一段关键讨论记录，说明自己如何处理 Hermes 提出的疑问。

**参考资料**

* 学会提问中的思考方法

### Day 3｜ 与 Hermes 一起研究和验证观点

哪些材料支持我的判断？哪些材料与之冲突？

**实践任务**

1. 将思考卡中的待验证问题交给 Hermes，让它整理已有资料并补充检索。
2. 要求 Hermes 为重要信息保留来源，区分原始材料、转述和无法核实的内容。
3. 自己打开关键来源，核对原文是否支持当前判断，再将发现的问题反馈给 Hermes。
4. 让 Hermes 根据核验结果更新素材清单和思考卡，提出提纲建议，由自己确认取舍。

**当日产出**

一份带来源的素材清单、一版确认后的提纲，以及观点是否发生变化的记录。

**参考资料**

* Hermes Web Search & Extract，了解搜索与网页读取的用途及限制。\
  <https://hermes-agent.nousresearch.com/docs/user-guide/features/web-search>

* Day 2 的证据评估资料。

### Day 4｜ 让 Hermes 执行内容创作

如何把自己的判断与材料，转化为读者能够理解的内容？

**实践任务**

1. 将确认后的思考卡、提纲、素材和表达要求交给 Hermes，让它先复述任务，检查理解是否一致。
2. 确认后，让 Hermes 起草正文；缺少依据的部分单独标记，不自行补造。
3. 自己逐段阅读，提出至少三条具体反馈，说明哪里不准确、不清楚或不像自己的表达。
4. 让 Hermes 根据反馈修改，并保存初稿、修改稿和关键修改说明。

**当日产出**

一篇完整初稿及修改版，以及能够体现人工判断的反馈记录。

**参考资料**

* Google Technical Writing One，选读清晰表达、段落组织与精简句子。\
  <https://developers.google.com/tech-writing/one>

### Day 5｜ 与 Hermes 一起编辑，并保存创作方法

这篇内容是否站得住？哪些有效做法值得保留？

**实践任务**

1. 让 Hermes 根据审核清单检查事实、来源、论证和表达，输出具体问题，不直接改动全部正文。
2. 自己核对重要问题，决定哪些修改应当采纳，再让 Hermes 完成定稿。
3. 请 Hermes 回顾前几天的协作记录，整理有效的创作步骤、表达要求和常见错误。
4. 自己确认适用范围，让 Hermes 创建内容创作 Skill，并用一个新的小任务运行测试，根据结果修正。

**当日产出**

一篇审核后的定稿，以及一份由 Hermes 保存、经过实际测试的创作 Skill。

**参考资料**

* Working with Skills，重点看创建、测试和更新 Skill。\
  <https://hermes-agent.nousresearch.com/docs/guides/work-with-skills>

* Persistent Memory，了解长期偏好如何保存。\
  <https://hermes-agent.nousresearch.com/docs/user-guide/features/memory>

**本期约定**

稳定偏好可以存入记忆和 SOUL.md，操作步骤放入 Skill，单篇文章的素材与进度保存在项目文档中。

### Day 6｜ 让 Hermes 执行自动化发布

如何让审核通过的内容，按指定时间发布到正确账号，并确认结果？

**实践任务**

1. 向 Hermes 提供目标渠道，让它检查发布工具、账号权限和缺失条件。凭据通过安全配置提供，不粘贴到打卡记录中。
2. 自己确认批准版本、目标账号、发布时间和授权范围，让 Hermes 整理发布任务卡。
3. 在本人授权的测试渠道，让 Hermes 执行一次短内容测试，核对目标、格式和链接。
4. 测试通过后，让 Hermes 为批准版本创建一次性定时发布任务，明确版本变化、重复发布和失败时的处理方式。
5. 发布后，让 Hermes 获取内容 ID 或链接，完成可用的回读检查并保存记录；接口无法回读的部分，由本人在目标端核对。

**当日产出**

一条由 Hermes 执行的发布流程，以及真实发布或测试投递记录。

**参考资料**

* Automate Anything with Cron\
  <https://hermes-agent.nousresearch.com/docs/guides/automate-with-cron>

### Day 7｜ 与 Hermes 一起复盘，验证能否继续使用

这套方法能否复用？自己的判断和 Hermes 的执行分别有哪些改进？

**实践任务**

1. 让 Hermes 汇总七天的项目材料，整理思考卡、作品版本、Skill 测试和发布记录。
2. 自己检查汇总是否准确，说明哪些关键判断由自己完成，哪些建议经过核实后被采纳或修改。
3. 将群友审阅或已有读者反馈交给 Hermes，让它归类问题、提出修改建议，由自己决定下一步。
4. 让 Hermes 更新确认后的 Skill，再提供一个新选题，运行一次精简流程，检查是否仍需要反复补充相同要求。

**当日产出**

完整项目记录、更新后的创作 Skill，以及一次新选题测试和改进计划。
