我原本准备以《扎根》作为主项目，但重新判断后换成了 Graph RAG。前者需要先由我独立阅读、形成判断，再让 Hermes 参与追问和核验；在只有七天的窗口里，过早让 Agent 介入容易把阅读变成对摘要的二次加工。Graph RAG 则已有明确的问题笔记，也能把问题界定、文献检索、证据检查、写作、编辑和 Skill 测试完整跑一遍。《扎根》保留为之后的长期写作计划。

本周我想把已有的 Graph RAG 问题笔记整理成一篇技术长文，关注 Agent 在已有图结构中如何决定检索路径和组织证据。我不想把它写成论文或模型的目录，而是想弄清楚：它什么时候真的改善检索，什么时候只是增加成本和不可解释性。

文章写给已经接触过 RAG、但不熟悉 Graph RAG 研究分支的中文技术读者。我会以可核验的文献为基础，区分论文实际报告的结果与自己的判断，也保留相互冲突的证据。

这周希望完成一篇可发布的技术长文、一篇可继续修改的社交媒体草稿，并简要记录 Hermes 如何帮助我检索、质疑、编辑和核验。有效做法等实际跑完后，再整理成可测试的 Skill。

### Day 2

今天我把研究主线收束为：检索控制权如何逐步交给 Agent，而不是把图构建与检索为何不能割裂作为本周要解决的中心问题。后一个问题当然重要，但如果一开始就追逐学术上更边缘的设定，工程验证很难界定变量，也难以做标准消融。这里优先选择的是一个能被明确反驳和比较的问题，而不是预先判断哪条研究线更本质。

我目前的工作假设是，Agent 的价值不在于抽象地让模型“更会走图”，而在于图并不完美、语料持续增量变化时，能够根据对问题和候选材料的理解选择下一步要看的语料。它或许能补偿固定遍历面对错误连接、缺失连接或过宽候选集时的刚性；但这只是待检验的解释，不等于 Agent 天然优于简单策略。

已有实践中的一个反例也提醒我，必须把收益归因放在中心：模型能力更强、能够阅读更多语料时，召回可能持续提升，而这未必是 Agent 架构本身的贡献。本周不提前承诺读者最后应当采用 Agent 还是固定检索；后续阅读和比较要尽量固定模型、语料与图，考察策略本身的差异，并明确任何判断只在给定语料和静态图等条件下成立。

# 2026-09-12

今天把 Day 2 的"逐步"落成可操作的框架：把检索策略的自由度拆成三个决策点——起点选择（从图的哪里开始检索）、下一步选择（每一步往哪走）、终止判断（何时认为证据足够、停止遍历）。每个决策点可以按固定规则、启发式、Agent 决定三种方式接管，一个检索策略就是三个决策点上的一组选择。这让"逐步把检索控制权交给 Agent"变成可枚举、可比较的配置，也直接服务 Day 2 的归因约束：比较时固定模型、语料与图，变量只是每个决策点由哪一层接管。

"把检索结果改写为新检索条件再查一轮"这类查询改写操作不单独列为决策点，并入下一步选择。这个拆分本身仍是待文献检验的假设：如果文献里出现不属于三个决策点的做法，例如一次性规划好整条遍历，而不是每走一步再决策，框架就要修正。

下一步用这套框架做文献归类，核对每个类别里是否有可核验的报告，特别是是否存在在同一图、同一语料上比较不同接管方式并报告结果的工作。

#### 首轮文献归类（九篇）

完成了首轮文献归类（9 篇公开论文，2024–2026，ICLR/ACL/EMNLP），检验结果：

* 三个决策点能覆盖全部 9 篇，没有策略需要新增决策点；
* 此前预留的修正条件触发了——RoG 和 PolyG 是"先整体规划、后确定性执行"，不逐步决策，框架需要再补一个维度**决策方式**：整体规划后执行，还是逐步迭代决策；三个决策点回答"决定什么"，决策方式回答"怎么决定"；
* 此前关心的关键问题得到否定回答——没有"同图、同语料、比较不同接管方式"的受控消融，最接近的是 ARK 在 STaRK 三张图上的对比，但部分基线数字引自原文，实验设置不完全统一。

两个与主线相关的发现：CatRAG 的 "Static Graph Fallacy"（固定转移概率导致语义漂移、多跳证据链断裂）是对 Day 2 工作假设最强的论文级支持，但其修复是启发式（按查询调整边权）而非 Agent，这让归因问题更尖锐——收益来自"对查询的感知"本身，还是来自"Agent 性"，现有证据不能区分；RJE 则表明终止判断可由小辅助模型完成，且显著减少 LLM 调用，接管程度是渐变的，不是"用 Agent / 不用 Agent"的二元区分。

这也暴露了长文的一个结构性机会：文献里没有一篇把接管方式或决策方式作为受控消融变量，这正是本文可以填补的空白。下一步把归类表读成文章骨架：按决策方式分两类（整体规划后执行 / 逐步迭代决策），每类内按接管方式展开，每类挑一篇代表作深读，并确认每篇实验报告的口径能否支撑"固定模型、语料、图"的横向比较。

# 2026-09-13

昨天重新 OCR 的九篇全文到手，第一件事是拿它核对 Day 3 的结论，结果推翻了其中一条——当时判断文献里没有接管方式的对照实验，依据只有摘要和结果段；全文里其实有四组。订正写进了归类笔记，这里只记结论的移动：**空白不在"没人做过对照"，而在"所有对照的另一头都是随机"。** 没有一篇把 Agent 和一个认真调过的启发式放在同一张图、同一语料上比。"Agent 比随机强"早有定论，也没什么信息量。

比订正本身更有用的是 ToG-R 那组：同一篇、同模型、同图，只把实体裁剪从 LLM 换成随机，性能基本持平，LLM 调用省掉将近一半；而 GraphReader 把节点选择换成随机，掉了 18%。**同样是把控制权交给 Agent，交在哪个决策点上，代价差得很远。** 这比 Day 3 说的"接管是渐变的"更具体，也正是三个决策点这个框架本该测出来的东西。

今天同时把本周的产出收窄。原计划是一篇公开长文，现在改成精简路线，只讲思路——三个决策点、决策方式，以及"对照的另一头全是随机"这个判断，不做论文目录。文献读到这一步已经能给出想法，但想法是否成立还得另行验证，那部分不属于本文。

动笔：策略罗列

下午开始写正文的第一部分，即九篇策略的罗列。定下几条：数字一概不出现，全部留给后面的讨论；读者预设为已经了解图结构与 RAG 的人，因此不解释基础概念。

原打算按发表年份分三段，Hermes 已经照此写完两段，我看后觉得生硬——年份在手，就按年份分章，但没人规定学术要按年审计。改为按策略形态分三个阶段：判断整体交给模型、按决策点重新分配、分岔。这个改动顺带解决了一个麻烦：PolyG 的会议信息一直存疑，按年份分段就得先核实，按形态分段则不必。

之所以把三个决策点放在正文里慢慢铺陈，而不是一开始就罗列下来，是因为包含逻辑关系的文字更易于阅读。

CatRAG 那段返工两次。它承接 HippoRAG 一系，用的是概率扩散而非逐步选路，前八篇里没有一篇需要边权这个概念，写到它时突然出现"边权重"，读者会接不上。补了一句机制说明后，篇幅又膨胀到五段，比其他论文多出一倍，看上去像在暗示它最重要。压回两段，把"查询感知其实只覆盖起点附近的局部"和"CatRAG 与 RoG 同为检索前集中调用模型"这两条留给讨论部分。

<br />

与 Hermes 的协作

今天大半时间花在挑语病上，挑出的毛病归成四类，已存为 skill：

一是替事实造气氛。Hermes 写"2024 年三篇方向一致得有些出奇"，但趋同有原因——当时大模型刚被证明能做多步决策，大家顺着同一条明显的路走。写成巧合就是往学术材料里掺悬念。

二是先否后肯的架子。"差别很大，但做的是同一件事"、"不是……而是……"。立一个假对立再收掉，读着有节奏，但那节奏是假的。这类句式改掉之后还会反复冒出来，每轮都得重新查。

三是比喻挤掉术语。"让模型充当在图上行走的人"——这句盖住了种子实体从哪来、裁剪宽度是固定的、最大深度是另一个终止条件。换成术语后段落变长，但每句都带信息。

四是机译腔与自造术语。"各自动了什么"、"拆"、"读成"都是英文结构直译；"三处判断"更麻烦——我已经定了"决策点"，另起一个词等于让读者多记一个不存在的术语。"剪枝"也换成了"裁剪"。

还有两条不属于文法：跨论文的绝对数字不可直接比较，各家的语料、图、模型、指标都不同，能用的只有各篇自己消融出来的相对落差；以及只读摘要和结果段下的结论不可靠——Day 3 那条被推翻的判断就是这么来的，消融实验、变体对比、附录实验都不进摘要。

分工上，我负责判断与改稿，Hermes 负责查证原文、起草和落盘。它今天自己发现归类表把 CatRAG 记成"全程无 Agent"是错的——动态边权那一步其实调用了 LLM，只是不在遍历过程中——这类核对是它比我快的地方。

# 2026-09-15

今天没有继续扩写正文，先把另外六篇论文按同一套问题重新核对：图从哪里来、节点上有什么、论文把什么当作检索失败、模型在哪个环节介入，以及对照实验实际替换了什么。前四篇只靠全文 OCR 订正过一次，剩下的论文还没有经历同样的核对；现在不能只用归类表安排文章的讨论部分。

 

这次核对也把 Day 4 的一句话改得更准确。"所有对照的另一头都是随机"说得太满：RJE 有从 topic entity 开始探索的变体，也有在判断后停止的变体；ARK 有把三个 agent 找到的节点随机重排的对照；CatRAG 则把按查询调整边权改回索引期固定的边权。它们替换的不是同一个决策点，不能并列成一类"Agent 对随机"的证据。

六篇论文也没有在回答同一个问题。ToG-2 直接讨论知识图谱不完整，并把图中已发现的实体和关系随机丢弃来测试稀疏图；ARK 关心种子实体不准后搜索被困在局部；CatRAG 关心固定边权把概率带向高度节点；RJE 关心已有证据是否足以作答；PolyG 关心问题结构与遍历策略是否匹配；KG-Agent 则基本假定图中已经有答案。它们都叫 Graph RAG，但把图当作可靠背景、会出错的索引，还是需要在查询时重新解释的对象，前提并不相同。

这使"隔空对话"的写法有了具体内容。文章应当从每篇论文要处理的失败写起：图缺信息、起点不准、边对当前问题不相关、候选过多，或问题类型不匹配；再写后来的方法怎样承接或绕开这个失败。CatRAG 与 ARK 提供了两条尚未直接比较的路线：前者为避免多步调用，把适应性放在检索前的一次边权调整；后者保留多步工具调用，用全局搜索重新定位。两篇互不引用，也没有在同一设置下比较，因此这里只能说明两种不同的成本安排，不能写成胜负。

另一个需要保留的限制是，跨论文主表的数字仍不可直接排队比较。ARK 的部分基线来自原论文或二手报告，ToG-2 也引用了一部分已有数字；即使同为 Hit\@1、Recall 或延迟，图、语料、模型和实现都不同。讨论里能稳妥使用的是单篇内部的消融，以及对实验设置是否统一的说明。
