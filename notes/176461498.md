# 2026-09-10

# Day 1｜与 Hermes 一起明确创作方向

## 一、选题

**AI Agent × Web3：从真实项目实践理解 AI Agent 如何连接区块链服务**

## 二、目标读者

主要面向刚开始了解 AI Agent 和 Web3 的大学生、开发者以及对 AI × Web3 感兴趣的初学者。

他们可能听过 AI Agent、区块链、MCP、x402、链上数据等概念，但对这些技术之间如何真正结合还缺少直观认识。

## 三、核心问题

AI Agent 不只是聊天工具，它怎样真正调用外部服务、获取链上数据，并完成一个具体的 Web3 任务？

通过一个真实项目的实践过程，把比较抽象的技术概念转化成容易理解的实际案例。

## 四、内容形式

以一篇**实践型技术分享文章**为主，按照“背景介绍 → 技术概念 → 实践过程 → 遇到的问题 → 最终结果 → 个人总结”的结构展开。

重点记录真实实践过程，而不是单纯介绍概念。

## 五、已有材料

目前可以使用的素材包括：

1. Hermes Agent 的学习笔记和安装、使用记录。
2. AI Agent × Web3 项目的开发记录、PRD 和技术方案。
3. x402、Agentic Payments、MCP、AI Judge 等相关学习资料。
4. ETHGlobal 黑客松项目实践过程中的项目讨论和技术记录。
5. 自己在实际开发过程中遇到的问题、报错、解决方法以及最终结果。

## 六、为什么选择这个选题

这个选题和自己的实际学习、开发经历直接相关，不需要完全依赖外部资料重新寻找案例。

同时，它能够把 Hermes 的学习过程和正在进行的 Web3 项目实践结合起来，最终形成一篇真正有实际内容的技术记录。

相比单纯介绍某一个技术概念，实践型文章更容易展示自己的学习过程，也方便之后整理成 GitHub README、技术博客或项目作品集内容。

## 七、七天预期成果

在七天内完成：

**1 篇完整实践文章 + 1 份项目实践记录 + 1 个可复用的技术案例。**

文章完成后，可以进一步整理到个人博客或 GitHub 项目中，作为 AI Agent × Web3 学习和开发经历的公开记录。

## 八、Hermes 协作方式

先让 Hermes 通过提问帮助进一步确认：

* 目标读者到底是 Web3 初学者还是有开发基础的人。
* 文章应该更偏技术教程还是项目实践记录。
* 哪些已有素材最适合作为核心案例。
* 哪些内容可以在七天内完成，哪些内容应该删减。

确认后，再让 Hermes 将讨论结果整理成创作任务卡，并保存到项目文档中。

# 2026-09-12

### Day 3｜与 Hermes 一起研究和验证观点

今天的重点从“提出观点”进一步进入了“验证观点”。我把思考卡中的待验证问题交给 Hermes，通过 Web Search & Extract 整理已有资料，并补充检索相关信息。

在整理材料时，我开始有意识地区分不同来源的可信度：优先查看官方文档、项目官网、论文等原始材料，再参考媒体报道和二次整理内容，对于来源不明或无法交叉验证的信息则单独标记，避免把转述内容直接当成事实。

完成初步检索后，我没有直接接受 Hermes 给出的结论，而是自己打开关键来源核对原文，重点检查材料是否真的能够支持原来的判断。这个过程让我发现，搜索结果中的“看起来合理”和“原文确实支持”是两回事，有些信息经过多次转述后会出现语义扩大甚至结论偏移。

根据核验结果，我再让 Hermes 更新素材清单和思考卡，并重新梳理文章提纲。最终保留了有明确来源支撑的观点，删除或弱化了证据不足的部分，也让后续写作有了更清晰的结构。

今天最大的收获，是开始建立自己的“研究—核验—修正”流程。Hermes 可以帮助我提高信息搜集和整理效率，但最终判断仍然需要自己回到原始材料进行核对。

### 当日产出

**带来源的素材清单：**\
对检索到的材料进行了分类，区分原始材料、二次转述和暂时无法核实的信息，并保留关键来源。

**确认后的提纲：**\
根据核验后的证据重新调整文章结构，将有证据支撑的内容放在核心位置，减少未经验证的延伸判断。

**观点变化记录：**\
原有观点整体方向没有发生根本变化，但经过来源核验后，对部分结论的表述进行了收缩和修正，避免把推测写成事实。

通过今天的实践，我更加明确了 Hermes 在研究中的定位：它更适合承担信息检索、材料整理和交叉验证辅助，而真正决定观点是否成立的，仍然是自己对证据的判断。
