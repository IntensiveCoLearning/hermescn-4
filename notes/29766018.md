## 一、今天实际发生了什么（真实案例）

今天让 Hermes 做两件事，过程本身就踩中了"会话管理"和"结果修正"的核心：

1. **更新 openclaw** —— 顺利。`npm ls -g` 查到是 npm 全局安装，`npm update -g openclaw` 从 `2026.9.1` 升到 `2026.9.4`。但 `openclaw --version` 一开始显示旧版 `2026.7.1-2`，排查发现机器上有**两个安装路径**（`/usr/local/bin` 和 `~/.local/bin`），是 PATH 顺序导致看到旧版。→ **教训：命令行工具的"版本"取决于哪个二进制被 PATH 先命中。**

2. **抓飞书内网表单生成开发文档** —— 坎坷。
   - `web_extract` 直接失败：内网地址被拦。
   - 改用浏览器，靠已登录态拿到了页面。
   - 但飞书是重 JS 的单页应用（SPA），`innerText` 一开始只有首屏，`scrollHeight` 卡住不渲染。
   - 找到真正的滚动容器 `.bitable-form-share-wrapper` 才加载出后续字段。
   - **关键突破**：通过交互测试发现"空间类型 = 应用空间"会**额外弹出 13 个字段**（必填数 5→16）——这是表单唯一的条件显隐逻辑。
   - 后期浏览器环境反复崩溃（页面变 `about:blank`、加载卡死、脚本被注入乱码），最终 13 个附加字段的**下拉枚举值没抓全**，只能诚实标注"待后台确认"。

→ 这两件事完美对应今天的主题：**怎么管理会话状态，怎么面对并修正不完整/出错的结果。**

## 二、核心概念：Hermes Profile（配置文件 / 画像）

**Profile = 一套独立、隔离的 Hermes 实例配置。** 每个 Profile 有自己独立的：

- `config.yaml`（设置）
- `sessions/`（会话历史）
- `skills/`（技能）
- `memories/`（记忆）
- `plugins/`、`cron/`（插件、定时任务）

**存放位置**：默认 Profile 在 `~/.hermes/`；其它 Profile 在 `~/.hermes/profiles/<name>/`，结构完全镜像。

**关键规则**：
- 同一时刻只有一个 Profile 处于 active。当前 session 的 skills/plugins/cron/memories 都来自 active Profile。
- **不要动别的 Profile 的东西**，除非用户明确要求——因为那会影响到一个完全独立的会话环境。
- 代码里解析路径用 `get_hermes_home()`，会话里用 `$HERMES_HOME`，**永远不要硬编码 `~/.hermes`**。

**为什么要理解 Profile**：它解释了"为什么换了个环境，Hermes 就不记得之前的设置/技能了"——因为不同 Profile 是隔离的。做环境迁移、备份、或给不同项目配不同 Hermes 人格时，操作的就是 Profile 目录。

## 三、管理会话（Session Management）

| 操作 | 方法 |
|---|---|
| 查命令 | `hermes --help` / `hermes <command> --help` |
| 交互会话 | `hermes`（默认 CLI）|
| 单次提问 | `hermes chat -q "..."`（无需 PTY，适合脚本）|
| 后台长跑 | `terminal(command="hermes chat -q '...'", background=true)` |
| 恢复最近会话 | `hermes --continue` |
| 恢复指定会话 | `hermes --resume <session_id>` |
| 交互式多开 | 用 `tmux`（Hermes 基于 prompt_toolkit，需要真终端）|

**多实例并行**（今天没用到但相关）：
- 快速子任务 → 用 `delegate_task`（共享进程、开销小）。
- 长时自主任务 → 用 `tmux` 起独立 `hermes` 进程（完全隔离、可交互）。
- 改代码时加 `-w`（worktree 模式）防 git 冲突。

**硬约束（会话层面绝不能破坏）**：
1. **不要破坏 prompt 缓存** —— 会话中途不要改历史上下文、工具集、系统提示。唯一例外是上下文压缩（compression）。
2. **消息角色必须交替** —— 不能连续两条 assistant 或两条 user，只有 tool 结果可以重复。
3. **密钥放 `.env`，设置放 `config.yaml`** —— 别把非密钥设置塞进 `.env`。
4. **不要手动改 `config.yaml`** —— 用 `hermes config set KEY VAL`，一个缩进错误就可能搞挂 live gateway。
