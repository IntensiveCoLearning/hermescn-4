暂定标题

同名用户说话，AI 却认错人：我如何用 Codex 定位并修复 Hermes Agent 的飞书共享会话身份丢失问题

<br />

目标读者

正在使用 Hermes Agent 接入飞书群聊的开发者；希望理解 Agent 如何协助真实开源修复的人；对 FDE 式“从用户问题到可验证交付”感兴趣的人。

<br />

核心问题

在飞书群共享会话中，不同用户可能使用相同的 display name。Hermes 保留了群内共享上下文，但进入 Agent 的消息只显示名字、不含稳定的 sender ID，因此模型可能认错人。简单开启 group\_sessions\_per\_user 虽然能区分用户，却会拆散群共享上下文，不符合实际协作场景。

<br />

内容形式

一篇带代码差异、测试证据和反思的技术复盘，重点呈现真实诊断过程，而不只贴最终代码。

真实飞书群使用问题；Codex 完整修复会话；Hermes Agent 源码和 Gateway 测试；PR #107120；Commit e586a1bc。

<br />

今天完成的工作

<br />

1．澄清问题边界

Codex 的第一版沿着“不同用户进入不同 session”的方向，尝试把 sender ID 加进 session key。进一步核对后发现，这会破坏群聊共享上下文。真正需要的是：共享同一个群 session，但每条进入 Agent 的消息都保留稳定的发送者身份。

<br />

2．完成最小可复用修复

在 Base Gateway 增加可扩展的 sender identity hook；Feishu Adapter 返回 sender\_id；共享群 session 的入站消息附带身份前缀；私聊不添加前缀；缺少 sender ID 时保持兼容。这样同名用户仍可被稳定区分，同时继续共享群聊上下文。

<br />

3．用测试锁定边界

新增测试覆盖：群聊消息包含稳定 sender ID；同名不同 ID 可区分；两人仍共享同一个 group session key；私聊不注入前缀；没有 identity 时维持原行为。

<br />

测试证据：第一版修改前为 4 failed、4 passed；修改后为 8 passed；纠正成“共享 session 加消息身份前缀”后，相关测试为 11 passed。完整 gateway 测试曾为 77 passed、1 failed，失败项是并发去重测试；单独重跑通过，因此如实记为疑似既有 flaky 行为，而不宣称整套测试全绿。ruff check、git diff check 和兼容性检查通过。

今天最重要的反思

这次最有价值的不是让 Codex 快速写出补丁，而是纠正了一个看似合理、实则破坏产品语义的方案：“身份归属”不一定应该进入“会话分区”。

<br />

群聊 session key 表达共享对话空间；sender ID 表达每条消息的来源。两者是不同维度。使用 Coding Agent 处理真实问题时，我仍需负责：明确不可破坏的产品语义；检查局部修复是否改变系统边界；用失败测试、回归测试和异常说明形成可审查证据。
