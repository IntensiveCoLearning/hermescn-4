《同名用户说话，AI 却认错人：我如何用 Codex 定位并修复 Hermes Agent 的飞书共享会话身份丢失问题》

<br />

\*\*目标读者\*\*

<br />

\- 希望理解 Agent 如何协助真实开源修复的人；

\*\*要解决的核心问题\*\*

<br />

在飞书群共享会话中，不同用户可能使用相同的 display name。Hermes 保留了群内共享上下文，但进入 Agent 的用户消息只显示名字、不包含稳定的 sender ID，因此模型可能无法区分同名用户。如果简单开启 \`group\_sessions\_per\_user\`，虽然能区分用户，却会拆散群共享上下文，不符合我们的协作场景。

<br />

\## 今天完成的工作

<br />

\### 1. 澄清了真正的问题边界

<br />

最初很容易把问题理解成“不同用户应该进入不同 session”。Codex 的第一版也沿着这个方向，尝试把 sender ID 加进 session key。

<br />

但进一步核对需求后发现，这个方向会破坏群聊共享上下文。真正需要的是：

<br />

\> \*\*共享同一个群 session，但每条进入 Agent 的消息都保留稳定的发送者身份。\*\*

<br />

所以最终没有修改共享 session 的划分方式，而是在消息边界补充身份信息。

<br />

\### 2. 做了最小、可复用的修复

<br />

修复没有写死在飞书消息处理主流程里，而是在 Base Gateway 增加可扩展的 sender identity hook：

<br />

\- 基类默认无额外身份信息；

\- Feishu Adapter 返回 \`sender\_id\`；

\- 对共享群 session 的入站消息添加发送者前缀；

\- 私聊不添加前缀，避免冗余；

\- 缺少 sender ID 时保持兼容。

<br />

最终送入 Agent 的群消息可表达为：

<br />

\`\`\`text

\[Alex Chen (sender\_id: ou\_alex\_001)]

Please review the deployment logs.

\`\`\`

<br />

这样即使两个人 display name 相同，Agent 仍可稳定区分；同时他们仍处在同一个群共享上下文中。

<br />

\### 3. 用测试锁定行为边界

<br />

新增测试覆盖：

<br />

\- 飞书群聊消息包含稳定 sender ID；

\- 相同 display name、不同 sender ID 能被区分；

\- 两人仍共享同一个 group session key；

\- 私聊不注入身份前缀；

\- 没有 identity 时维持原行为。

<br />

Codex 过程中的测试证据：

<br />

\- 第一版修改前，新增定向测试出现 \`4 failed, 4 passed\`；

\- 第一版修改后，定向测试变为 \`8 passed\`；

\- 修正为“共享 session + 消息身份前缀”后，相关定向测试为 \`11 passed\`；

\- 完整 gateway 测试出现过 \`77 passed, 1 failed\`，失败项是并发去重测试；该测试单独重跑通过，因此如实记录为疑似既有 flaky 行为，而不把整套测试描述成全绿；

\- \`ruff check\`、\`git diff --check\` 和兼容性检查通过。

\## 今天最重要的反思

<br />

这次最有价值的并不是让 Codex 快速写出补丁，而是发现并纠正了一个看似合理、实则破坏产品语义的方案：

<br />

\> \*\*“身份归属”不一定应该进入“会话分区”。\*\*

<br />

群聊的 session key 表达的是共享对话空间；sender ID 表达的是每条消息的来源。这是两个不同维度。把两者混在一起，代码可能通过测试，却会改变真实协作方式。

<br />

因此，使用 Coding Agent 处理真实问题时，我需要负责三件事：

<br />

1\. 明确不可破坏的产品语义；

2\. 检查 Agent 是否在修复局部问题时改变了系统边界；

3\. 用失败测试、回归测试和异常说明形成可审查证据。

<br />
