暂定标题

同名用户说话，AI 却认错人：我如何用 Codex 定位并修复 Hermes Agent 的飞书共享会话身份丢失问题

<br />

目标读者

正在使用 Hermes Agent 接入飞书群聊的开发者；希望理解 Agent 如何协助真实开源修复的人；对 FDE 式“从用户问题到可验证交付”感兴趣的人。

<br />

核心问题

在飞书群共享会话中，不同用户可能使用相同的 display name。Hermes 保留了群内共享上下文，但进入 Agent 的消息只显示名字、不含稳定的 sender ID，因此模型可能认错人。简单开启 group\_sessions\_per\_user 虽然能区分用户，却会拆散群共享上下文，不符合实际协作场景。

<br />

内容形式

一篇带代码差异、测试证据和反思的技术复盘，重点呈现真实诊断过程，而不只贴最终代码。

<br />

已有一手材料

真实飞书群使用问题；Codex 完整修复会话；Hermes Agent 源码和 Gateway 测试；PR #107120；Commit e586a1bc。

<br />

今天完成的工作

<br />

1．澄清问题边界

Codex 的第一版沿着“不同用户进入不同 session”的方向，尝试把 sender ID 加进 session key。进一步核对后发现，这会破坏群聊共享上下文。真正需要的是：共享同一个群 session，但每条进入 Agent 的消息都保留稳定的发送者身份。

<br />

2．完成最小可复用修复

在 Base Gateway 增加可扩展的 sender identity hook；Feishu Adapter 返回 sender\_id；共享群 session 的入站消息附带身份前缀；私聊不添加前缀；缺少 sender ID 时保持兼容。这样同名用户仍可被稳定区分，同时继续共享群聊上下文。

<br />

3．用测试锁定边界

新增测试覆盖：群聊消息包含稳定 sender ID；同名不同 ID 可区分；两人仍共享同一个 group session key；私聊不注入前缀；没有 identity 时维持原行为。

<br />

测试证据：第一版修改前为 4 failed、4 passed；修改后为 8 passed；纠正成“共享 session 加消息身份前缀”后，相关测试为 11 passed。完整 gateway 测试曾为 77 passed、1 failed，失败项是并发去重测试；单独重跑通过，因此如实记为疑似既有 flaky 行为，而不宣称整套测试全绿。ruff check、git diff check 和兼容性检查通过。

今天最重要的反思

这次最有价值的不是让 Codex 快速写出补丁，而是纠正了一个看似合理、实则破坏产品语义的方案：“身份归属”不一定应该进入“会话分区”。

# 2026-09-11

HermesCN 残酷共学第三期｜Day 2 打卡

今天我突然想通了一件事：我之前的文案 AI 味太重，可能不只是文案写得不好，而是整个顺序错了。

我原来的做法接近于：先让 AI 生成一份完整逐字稿，我再对着它录。这样录的时候，我一直在注意自己有没有念错、有没有漏字。哪怕文案内容没问题，说出来还是很像朗读，不像我真的在跟人讲一件自己想明白的事情。

今天我试着把顺序倒过来。

先不要让 AI 写逐字稿。我直接对着录音断断续续地说，把想到的观点、例子、犹豫和重复都说出来。这一遍不追求能发布，只是把我脑子里真实存在的东西倒出来。

然后把语音转成文字，交给 Hermes。它不负责把文字润色成一篇可以照念的稿子，而是帮我找到主线：我的核心判断是什么，前后因果怎么连接，哪些地方重复了，哪里缺了一个例子，哪里其实还只是一个假设。

今天 Default Profile 里的真实对话也是这样。我先零散口述了一段“额度焦虑会限制人探索 AI 边界”的观点。Hermes 把它整理成了“额度焦虑 → 不敢尝试 → 错过 Aha Moment；额度充裕 → 放开尝试 → 发现新能力 → 联想到更多任务”。

我随后提出，不要再给我完整文案，只要给我更详细的思路大纲，我看着大纲自己完成整段论述。第一版大纲出来后，我又觉得逻辑节点太少，要求继续加密。这个过程让我意识到，我真正需要的不是几个关键词，也不是一篇逐字稿，而是一张“论述路标”。

它应该细到让我知道下一段要回答什么、用哪个例子、怎么接到后面；但不能细到把每一句话都替我写好。具体怎么找词、哪里停顿、临时补一句什么，仍然由我在录制现场决定。

正式录制时，也不必追求一镜到底。我可以盯着路标，一次讲完一个完整意思。中间气口不对、表述绕了、事实说错，就只把这一小段重新说一次。自然的停顿和轻微自我修正不一定都要删，因为那些可能恰恰是人在思考的痕迹。

最后，再把原视频、重录片段和论述路标交给 Codex，让它调用剪辑工具处理废片、长空白和重复 take，按逻辑顺序拼接，输出初剪和剪辑清单。

目前我还不能说 Codex 一定能“剪得很好”。这只是我今天准备验证的假设。真正完成一次素材导入、自动剪辑和人工验收以后，才能判断它是否可靠。

我的当前方法可以概括成：

自由口述 → 语音转文字 → Hermes 整理主线 → 生成详细论述路标 → 看路标分段重录 → Codex 技术剪辑 → 本人验收

今天的事实、假设和判断如下。

事实：过去照着 AI 完整文案录制时，我有明显的念稿感。今天我已经尝试用自己的原话先说，再让 Hermes 整理结构；我也明确要求它不要提供固定台词，而是增加逻辑节点。

假设：不用逐字稿、改看论述路标，能够降低 AI 味；分段录制能减少长段表达压力；Codex 能把多段 take 剪成自然成片。

当前判断：AI 不应该在人开口之前，先决定他要说的每一句话。它更适合在人已经表达之后整理结构，在人重新录完之后执行技术剪辑。

最强的反对意见是：没有逐字稿可能让表达变散，遗漏关键数字和事实，后期剪辑也可能更费时间。

我的回应是：不是完全无稿，而是从“句子级控制”改成“逻辑节点级控制”。数字、来源和不能说错的边界仍然单独做成事实卡，但不把整段话固定下来。

什么会让我改变判断：我会用真实口播做一次验证。如果路标版在自然度、逻辑完整、录制耗时和剪辑耗时上并没有改善，就调整大纲粒度，或者改成“关键句固定、其余自由表达”的混合方式。

我今天最重要的发现是：

人味不一定要在 AI 写完之后再想办法加回去。更好的办法，可能是一开始就不要把自己的表达权交出去。
