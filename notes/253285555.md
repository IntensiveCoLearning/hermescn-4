## 学了什么

- Ethereum 节点由 execution client 与 consensus client 协作；execution client 处理交易和状态，consensus client 负责 PoS 共识；
- Indexer 在链数据之上构建面向查询的派生模型，The Graph 的 POI 用于表达某个 subgraph 已正确索引到指定区块；
- 交易要区分签名、节点验证、mempool、纳入区块、observed、confirmed、finalized 和 business applied；
- Ethereum PoS 的 finality 依赖 checkpoint 与 supermajority link，`confirmed` 则是应用定义，不能跨链互换；
- reorg 需要保留旧分支、回退到共同祖先、撤销旧派生状态并 replay 新 canonical 分支；
- 幂等处理需要把 observation key、business event key、inbox、状态机、outbox 和下游幂等分层；
- reconciliation 必须比较 canonical chain、raw observation、Indexer read model、业务状态和外部副作用。

- 读取并核验 Ethereum 官方 Nodes and Clients、Transactions、Blocks 和 Proof-of-Stake 文档；

# 残酷共学打卡 · 2026-09-16

## 今日主题：个人工程案例——把经历转化为面试证据

🟩 **SUCCESS｜今日资料整理验收**

今天围绕 Parallax pipeline Robot 主案例和 Telegram Robot 辅助案例，完成了个人工程经历的证据化整理。重点不是把目标流程包装成“已经全自动”，而是把真实故障、可验证假设、改进设计和未知边界分开。

## 学了什么

- Agent 是阶段执行者，不等于工作流状态机；入口、编排、执行和外部系统需要分层；
- Coder → Reviewer → Delivery → PR 可以抽象成带版本、attempt、错误分类和人工接管的状态机；
- Reviewer 通过后没有自动进入 Delivery 是故障现象，具体根因必须按状态写入、事件派发、Worker 消费、并发竞争、展示刷新和外部依赖逐层核验；
- 阶段级幂等需要稳定 `stage_key`、条件更新、结果引用和受限重试；外部副作用状态不明确时不能直接重放；
- Telegram 更适合作为交互入口和进度展示层，消息本身不等于后端权威状态；
- PR 创建是外部交付动作，请求成功不等于目标 PR、分支、CI 和最终结果已经回读核验；
- 面试中的个人案例应该同时说明目标、当前实现边界、失败现象、排查路径、改进方案和未知项。

## 做了什么

- 回读 Day 1 / Day 2 的项目案例和 Telegram 任务记录，确认主案例、辅助案例、目标流程和已知 Delivery 断点；
- 复用 Day 3 已核验的 Coinbase、Dune、Alchemy 公开岗位信号，映射可靠 API、事件驱动、reconcile、分布式系统、可观测性、测试和故障响应能力；
- 读取 AWS Step Functions、OpenTelemetry、Telegram Bot API 和 GitHub Pull Request REST API 官方资料，整理状态机、错误恢复、跨阶段关联、通信接口和外部 PR 交付的通用技术边界；
- 形成 `docs/day6-personal-engineering-case-research.md`，包含 60 秒面试复述、六层故障排查模型、状态机 / 幂等 / 可观测性设计、岗位映射和 10 张问题卡片；
- 执行离线结构验收，确认没有编造吞吐量、延迟、SLO、成功率、PR 数量或故障根因。

## 得到了什么结果

- 能够把“Reviewer Pass 后没有自动进入 Delivery”的真实现象讲成可验证的系统可靠性问题，而不是掩盖成成功；
- 形成从真实目标到当前边界、故障、分层核验、改进设计和回读验收的完整表达；
- 明确 Telegram 可见进度、编排状态、Worker 执行和 PR 外部结果属于不同证据层；
- 形成 10 张个人案例 / 岗位相关自拟问题卡片，并保留真实面试归属的 `unknown` 边界。

## 遇到什么失败 / 卡点

当前只能从项目内用户描述核验案例事实，尚未读取外部 Parallax 代码、运行日志或部署状态，因此无法定位 Reviewer Pass 后未进入 Delivery 的具体根因。案例的吞吐量、延迟、SLO、自动推进成功率、人工介入率和 PR 成功率也没有实测数据，继续保持 `unknown`。
