## 今日主题：明确 Web3 技术面试资料整理方向

今天开始了 HermesCN 新一期七天共学。本期不再以介绍 Hermes 基础功能为主，而是围绕一个真实目标展开：让 Hermes Agent 帮助我调查、核验和整理 Web3 技术面试资料，最终服务于中级或高级 Web3 后端、基础设施工程师岗位的面试准备。

## 创作与学习目标

我计划将最终成果整理为一篇 X 长帖，目标读者是我自己以及对 Hermes Agent 和 Web3 技术感兴趣的技术爱好者。

这次资料整理不会停留在泛泛罗列面试知识点，而是要求先调查真实的面试题、岗位要求和实际应用场景，再进行结构化整理。资料需要区分真实面试题、岗位要求、真实工程场景、技术依据和自拟练习题，并为重要信息保留来源。无法核验的内容要明确标记为 `unknown`，不能把自拟问题包装成真实面试题。

## 面试资料范围

本期资料调查暂定按以下顺序推进：

1. Go 后端基础：并发、`context`、错误处理、重试、测试和服务设计；
2. Web3 RPC：JSON-RPC、`eth_call`、节点错误、限流、区块状态和数据可靠性；
3. Web3 基础设施：节点、Indexer、交易生命周期、链重组、最终性和数据一致性。

目标岗位主要是交易所相关的中级或高级 Web3 后端、基础设施工程师，面试语言为中文或中英文混合。

## 真实项目案例

本期主要使用 Parallax pipeline Robot 作为自己的实践案例，并以 Telegram Robot 作为辅助案例。

Parallax pipeline Robot 目前集成了 Coder、Reviewer 和 Delivery Agent，三个 Agent 共同负责从开发、Review、Delivery 到创建 PR 的完整 Workflow。当前的使用方式是由 Codex 整理任务 prompt，再手动粘贴到 Telegram Robot 的聊天窗口中；Telegram Bot 主要负责展示对话和各阶段进度，Hermes 则负责底层 Agent 的具体实现。

目前 Workflow 仍不是完全自动化的。最近出现过 Reviewer 通过后没有自动进入 Delivery 阶段的情况，最后需要手动触发 Delivery Agent。这个问题说明阶段之间的自动状态传递和失败恢复仍需要完善，暂时不能把整个流程描述成已经完全自动完成。

我的最终目标是让任务能够自动经过：

```text
任务输入 → Coder 开发 → Reviewer 审查 → Delivery 执行 → 创建 PR
```

并且在某个阶段中断时能够明确记录状态、判断是否重试、避免重复执行已经完成的阶段，并在必要时通知人工。
